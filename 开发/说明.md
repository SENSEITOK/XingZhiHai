# 开发资料（不属于游戏）

这个文件夹不进压缩包，游戏也不读它。里面是 beta20 做到一半的东西和测试脚本，留着下次接着做。原著和读书笔记不在这里，也别放进来。

## 里面有什么

- `design/`：beta20 的总计划 `PLAN.md`，加上法术（`spec_spells.md`）、空岛（`spec_isle.md`）、战争（`spec_war.md`）三份方案。
- `i3d/`：空岛 3D 的源码和工具。
  - `geo.js`、`geo2.js`、`render.js`：渲染和造型的底子；`embed.py` 把它们和模型拼成 `isle3d.js`，再写进游戏。
  - `models/`：二十个模型文件。其中十种设施是新做的，还没进游戏：哨塔、兵营、停鸡坪、酒馆、浴场、展馆、龙场、猫舍、观星台、防风屏障。它们在 1994、2077 两条线各有一套，三个等级加待修状态都有。
  - `review/audit.cjs`：查面数、亮度、占地、动件这些硬指标；`rv2.sh` 和 `review/ad_*.sh` 拍复查截图。
- `sim/`：测试脚本。
  - `eq_regress.cjs`：装备卸下、装上的回归测试（317 项）。
  - `voice_check.cjs`：原著人物说话样例（16 项）。
  - `alt/run_all.sh`：种族、梅网、异界位置、对白卡，桌面和手机各跑一遍。
  - `brk250r3_speaker/`：对白卡 100 例，新旧两版对比。

## 怎么用

1. 把整个「开发」文件夹复制到仓库外面的工作目录再跑，别在仓库里直接跑，测试会生成输出文件。
2. 在复制出来的文件夹里跑 `sh 还原路径.sh <仓库路径> [原著目录]`。脚本里的路径存成了占位符：`@@SP@@` 是这个文件夹，`@@REPO@@` 是仓库，`@@NOVEL@@` 是原著所在的目录。它还会做两件事：从游戏里取出 three.js 放到 `i3d/build/three.bundle.js`；从 git 取出加种族之前的旧版页面 `sim/alt/index_pre_p250r.html`，对比测试要用。
3. 3D：先跑 `python3 i3d/embed.py --build-only` 拼出 `isle3d.js`，再跑 `node i3d/review/audit.cjs` 查指标。直接 `python3 i3d/embed.py` 会把模型写进游戏，新模型还要先在游戏的设施目录（FACTAB）里登记价钱、维护费和收益。
4. 测试要用 Playwright 和 Chromium，跑法和以前一样。

## 生图的规矩

NovelAI 账号被封过。当时脚本两张之间只隔二十来秒，一小时最多跑了 165 张，一天六百多张。以后不管用哪家生图：

- 开跑前先问用户，确认对方没在网页上同时生图。一次只发一个请求，不并发。
- 两张之间至少隔 60 秒；每小时不超过 30 张，每天不超过 150 张。量大就分几天跑。
- 先试几张，确认效果再放量。一旦开始扣点数，就停下来问。
